# 演进路线图

> 产品定位与原则见 [vision.md](vision.md)：Reflector 是一面诚实的镜子——基于真实证据的自我认知系统。

Reflector 的核心属性：**个人数据资产 + 反思 + 学习 + 个人成长**。

录音只是输入源之一。最终形态：所有个人数据（对话、反思、上传的文档、笔记、收藏）沉淀为归用户所有的数据资产，AI 在资产之上驱动反思与学习，输出个人成长。北极星指标是**每周「被看见时刻」数**（用户确认洞察说中了自己），而非录音时长或打开次数。

```
M1 (已完成)        M2 情境化        M3 成长闭环 + 资产层           M4 增强
录音→转写→反思 →  何地 + 何人  →  日报/承诺/检索/资产库/上传  →  教练/学习闭环/图谱
```

---

## M1 — 核心录音管线（已完成）

- 录音 5 分钟分片上传（RN/Expo → FastAPI）
- WhisperX 转写 + 说话人分离（SPEAKER_00/01...）
- LangChain 多 Provider AI 分析（per-chunk + per-session 全局分析）
- 会话时间线浏览

---

## M2 — 情境化：何地 + 何人（~4 周）

把匿名的转写记录升级为「张三 周三早晨 在公司会议室 说了什么」。

详细设计见 [design-context.md](design-context.md)。

### 功能清单

| 功能 | 说明 |
|------|------|
| 位置采集 | 录音开始取 GPS，位移 >100m 补点；逆地理编码 |
| 语义地点 | `places` 表：用户给常用地点起别名（家/公司/健身房），geo-fence 自动匹配 |
| 声纹身份 | `speakers` 表：声纹 embedding 匹配，SPEAKER_xx → 真实姓名 |
| 说话人认领 | 回放 UI 一次性标注「这是张三」，声纹入库后自动识别；支持纠错回写 |
| 语义时间 | 派生"工作日早晨/周末深夜"，注入分析 Prompt |
| Prompt 升级 | 反思分析携带 地点/参与人/时间语境 |

### 依赖

- 移动端：expo-location 权限与采集
- 后端：pgvector 扩展（声纹 embedding 存储与余弦检索）
- 管线：声纹提取必须在 `process_chunk` 内完成（音频处理后即删）

### 验收标准

- 新会话详情页显示语义地点（命中 places 时显示别名，否则显示逆地理地址）
- 已认领的说话人在后续录音中自动显示真实姓名，准确率 ≥90%（同设备、安静环境）
- 反思报告中出现情境化描述（如「在公司与张三的讨论」）

---

## M3 — 成长闭环 + 资产层（~5 周）

让分析从「单次会话」升级为「跨会话的成长视角」，同时建立个人数据资产底座。

详细设计见 [design-growth.md](design-growth.md)（反思/承诺/检索）与 [design-knowledge.md](design-knowledge.md)（资产/知识库）。

### 功能清单

| 功能 | 说明 |
|------|------|
| L2 每日反思 | Celery Beat 定时任务，聚合当日所有 session 摘要生成日报 |
| 承诺追踪 | 从 action_items 升级为 `commitments` 表（open/done/dropped 状态机） |
| 回忆检索 (RAG) | segments/summaries 向量化入 pgvector，自然语言问答 `POST /ask` |
| 统一资产模型 | `assets` 表：对话/反思/日记/文档/笔记/链接统一沉淀，可检索可标签 |
| 用户上传 | PDF/Word/Markdown/笔记/链接上传，文本提取 → 向量化 → 入知识库 |
| 全量导出 | `GET /export` 一键导出全部个人数据资产（Markdown + JSON） |
| 复习与检验式回顾 | 知识卡进入间隔重复队列，AI 提问检验（提取练习），随日报推送 2-3 张（见 [design-learning.md](design-learning.md)） |
| 学习缺口检测 | L2 日报附带扫描：从对话中发现知识盲区/重复模式，建议学习主题（用户确认才创建） |

### 依赖

- M2 的情境数据（地点/人物）让日报和检索的质量显著提升，建议 M2 先行
- Embedding 模型选型（本地 bge-m3 或 API）；资产检索复用同一套 embeddings 基建

### 验收标准

- 每日 22:00 自动生成日报：时间分配、关键对话、承诺清单、3 个反思问题
- **北极星检验**：日报洞察被用户标记为「准」（被看见时刻）每周 ≥3 次，且每条洞察可点开回溯证据
- 「上周张三跟我说的预算是多少」能检索出正确的 utterance 及出处
- 承诺在日报中持续追踪直到关闭
- 上传一份 PDF 后，`POST /ask` 能检索到其中内容并附出处
- `GET /export` 导出的内容覆盖全部资产类型，可离线阅读

## M4 — 增强：教练、习惯、图谱（按数据反馈排序）

| 功能 | 说明 | 前置 |
|------|------|------|
| AI 教练对话 | 基于 RAG 的对话界面，教练能引用真实历史记录 | M3 RAG |
| 技能模型与证据轨迹 | 技能水平不打分，呈现来自真实对话的正/反例证据（见 [design-learning.md](design-learning.md)） | M2 声纹（识别"我"） |
| 练习意图 + 应用检测 | 录音前设定刻意练习意图，AI 在转写中检验执行；被动检测知识被实际运用 | 技能模型 |
| 学以致用周报 | 输入→内化→运用的学习闭环健康度，标出从未运用的收藏 | L3 + 技能模型 |
| 目标系统 | 用户设定目标，AI 对照事件流评估真实投入 | M3 日报 |
| 习惯追踪 | 地理围栏自动打卡（到健身房 = 运动记录） | M2 places |
| 人际关系图谱 | 交流频率、话题分布、关系冷热变化 | M2 speakers |
| 情绪曲线 | 按天/周可视化，关联触发因素（人/地点） | M2 + M3 |
| 周/月深度洞察 | 跨天模式挖掘（L3） | M3 日报 |

M4 内部优先级在 M3 上线后根据实际使用数据决定。M4 验证的核心问题（见 [vision.md](vision.md)）：「教练比朋友更懂我吗」——基于全量历史的对话能否产生朋友给不了的问题。

---

## 贯穿性约束

1. **隐私**：音频转写后即删（现有设计保持）；声纹/位置数据本地化存储；送第三方 LLM 前可配置人名脱敏。
2. **成本**：L2/L3 只喂摘要不喂原文；长会话 map-reduce 汇总。
3. **架构**：保持模块化单体 + PostgreSQL（含 pgvector），不引入微服务和独立向量库。
4. **可追溯**：所有 AI 洞察附带证据引用（session/segment id），用户可点开验证。
